# Alt+Tab window switcher: design

Date: 2026-10-27. Branch: `window-switcher`. Part of the fledge shell (project A).

## Why

The user: "an alt tab interface that will move between windows showing a
preview (this should be as computationally efficient as possible), when the
window is selected that should be brought to focus and if it's on a different
virtual desktop that should be made active".

Until now Alt+Tab was `window.cycle_next` + `bring_to_top`: no UI, workspace
order, current workspace only.

Success: holding Alt and pressing Tab shows every window, most recently used
first, with a thumbnail; Tab / Shift+Tab (or the arrows) step; letting go of Alt
focuses the pick and switches to its workspace (and monitor). A quick tap goes
straight back to the previous window without showing anything.

## How it is driven

Hyprland drives it; the shell only listens and draws. No process is spawned per
keypress, nothing polls, and the panel never takes the keyboard.

- **The bind** (`windows.focus-on-next-window`, ALT+TAB; the `previous` one
  ALT+SHIFT+TAB) is two dispatches: `event "fledge-switcher next|prev"` (a
  `custom>>` line on Hyprland's event socket, which Quickshell already reads)
  and `submap "fledge-switcher"`. Entering the submap inside the bind is
  synchronous, so a tap faster than the shell can't be lost.
- **The submap** (generated by `gen-binds.jq`, only when some bind sends the
  `next` event) repeats each switcher bind's keys with just the event, adds
  Right/Left (next/prev), Return (commit) and Escape (cancel); the last two
  leave the submap in the same bind. Any bind the user points at the event
  gets its keys repeated here, so rebinding it to Super+Tab works.
- **Letting go of the modifier** can't be a release bind: Hyprland fires a
  modifier's release bind only when no other key came between press and
  release. `hypr/fledge/switcher.lua` instead listens for `keybinds.submap`;
  on entering `fledge-switcher` it notes which of Alt/Super/Ctrl (left, right)
  are held and subscribes to `input.keyboard.key` until none is, then sends
  `commit` and resets the submap. The key subscription exists only while the
  switcher is up. Seen in the VM: a modifier release reaches the callback
  twice, the second time with `hl.is_key_down` updated; a one-shot `hl.timer`
  can't be re-armed, so the check is in the callback. A bind with no modifier
  leaves nothing to let go of: Return or a click picks.
- **The shell** (`switcher/Switcher.qml`) keeps the most-recently-used order
  from `activewindowv2` / `closewindow` events, seeded once from
  `hyprctl clients -j` (`focusHistoryID`). On the first `next`/`prev` it
  snapshots the windows in that order; `commit` focuses the pick with one
  `hyprctl eval` (`focus({ window = "address:0x…" })` + `bring_to_top`):
  focusing a window on another workspace or monitor switches there. It closes
  if the submap is left any other way (a reload), and at start the shell resets
  a stale `fledge-switcher` submap like the `fledge-record` one.

## Turning it off

`windows.switcher` (default `true`), a toggle at the top of Settings › Keybinds.
Off, `gen-binds.jq` renders any bind sending a `fledge-switcher` event as the old
`window.cycle_next` (`false` for `prev`) + `bring_to_top`, drops its submap step
and generates no `fledge-switcher` submap: Alt+Tab cycles focus with no panel.
The binds themselves don't change, so turning it back on restores the switcher
and any keys the user gave it. The shell keeps only its focus-order list.

## Cost

- A tap (release within 120 ms) never maps the panel or captures anything.
- Thumbnails are `ScreencopyView` with `live: false`: one frame per window,
  taken when its tile appears. The strip is a `ListView` with `cacheBuffer: 0`,
  so only tiles in view exist and capture.
- The panel is a centred layer surface the size of the strip (no full-screen
  dim), with no keyboard focus, so the focused app never sees a focus change.
- Idle cost: one array update per focus change.

## Not done

- Windows aren't filtered by monitor or workspace: all of them are listed.
- No live thumbnails while the switcher is up (a deliberate trade for cost).
- Releasing the modifier needs a real keyboard: `verify-shell.sh` drives the
  events and submap the way the binds do; the release path was checked in the
  VM with QEMU key events.
