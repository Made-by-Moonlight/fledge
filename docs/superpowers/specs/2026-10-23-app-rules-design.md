# Per-app window rules: design

Date: 2026-10-23. Branch: `app-rules`. A follow-up to the fledge shell
(project A): a Settings page that lists apps and sets, per app, the opacity of
its windows and where they open.

## Why

Per-app opacity and placement are hard-coded in
`dot-config/hypr/fledge/rules.lua`: a default of 0.97 focused / 0.9 unfocused
on every window, 1.0 / 0.97 on browsers, opaque Vesktop, YouTube Music, Zen,
QEMU, RetroArch and Steam, and Vesktop, Spotify and YouTube Music on workspace
9. Changing any of it means editing Lua. The user asked for "a setting panel
that allows me to set per application transparency, it should scan current
applications and allow me to configure monitor binds (if any) and set the
opacity for its family of windows".

Success: Settings › Apps lists the apps that are open (and the ones already
configured), and for each one the person sets a focused and an unfocused
opacity and pins it to a workspace or a monitor. Open windows take a new
opacity straight away; everything the hard-coded rules did, the page now
shows and can change.

## Decisions (the user's)

- **Placement:** a monitor *or* a workspace. "Monitor binds" means where an
  app's windows open, not a keybind.
- **Opacity:** two values, focused and unfocused, as the default already is.
- **Existing rules move into the page:** the per-app opacity and placement in
  `rules.lua` become default entries in `settings.json`, so they show up and
  can be changed. Behaviour is unchanged until edited.
- A "family of windows" is a window class: every window Hyprland reports with
  that class.

## Non-goals

- Other rule kinds (float, size, blur, no_screen_share, tags): `rules.lua`
  keeps them.
- Matching by title or by regex. Keys are exact classes. The two pattern
  rules that set opacity stay hard-coded (see "What moves").
- Moving windows that are already open to a new workspace or monitor:
  Hyprland applies placement when a window opens. The page says so.
- A keybind that sends an app's windows to a monitor.

## Settings

Two new sections, merged and validated like the others (`check.jq`, and the
schema in the shell spec):

```json
"windows": { "opacity": { "active": 0.97, "inactive": 0.9 } },
"apps": {
  "vesktop": { "opacity": { "active": 1, "inactive": 1 }, "workspace": 9 },
  "spotify": { "workspace": 9 },
  "kitty":   { "opacity": { "active": 0.9, "inactive": 0.75 }, "monitor": "desc:BNQ BenQ EX2780Q W4L08254019" }
}
```

- `windows.opacity`: the default for every window without its own.
- `apps.<class>`: any of
  - `opacity`: `active` and `inactive`, each 0.1 to 1 (below 0.1 a window is
    effectively lost); both required when `opacity` is there.
  - `workspace`: a workspace number, 1 or more; or
  - `monitor`: a monitor key as Displays writes them (`desc:<description>` or
    a connector name), no comma.
  - `workspace` and `monitor` together are refused: one placement.
- The class is the key: not empty, any characters (the generator quotes it
  for Lua and escapes it for Hyprland's regex match).
- An app overridden with `null` in the user file is removed, as binds and
  workspaces are: that's how a default entry is forgotten. So is a single
  field set to `null` (the page clears a shipped entry's opacity or
  placement that way, and switches placement in one write: the old field
  `null`, the new one set). `"apps": null` drops every app.
- A class with `"` or `\` can't be a settings path (`valid_path`), so the
  page shows such a row read-only and says to edit the file.

## Generated config

`fledge settings apply` writes a fifth file, `~/.local/state/fledge/hypr/apps.lua`
(`gen-apps.jq`), loaded with the others after `rules.lua`, so a page entry
wins over anything hard-coded:

```lua
-- Generated by `fledge settings apply`. Do not edit.
hl.window_rule({ match = { tag = "default-opacity" }, opacity = "0.97 override 0.9 override" })
hl.window_rule({ match = { class = "vesktop" }, opacity = "1 override 1 override" })
hl.window_rule({ match = { class = "vesktop" }, workspace = "9" })
hl.window_rule({ match = { class = "com\\.libretro\\.RetroArch" }, opacity = "1 override 1 override" })
```

- `override` makes the value absolute (not multiplied by Hyprland's global
  `active_opacity`), as the hard-coded app rules did.
- The `default-opacity` tag stays in `rules.lua` (every window, minus the
  ones it opts out), and its opacity rule moves here.
- Rule fields checked in the VM (Hyprland 0.56): `opacity`, `workspace`
  (`"9"`), `monitor` (`desc:…` or a connector); unknown fields are refused.

## Applying, and live changes

- Every change saves through `fledge settings set … && apply`, the same path
  as the other pages; apply reloads Hyprland.
- **Hyprland re-applies opacity rules to open windows on reload** (checked in
  the VM: 0.97/0.9 → 0.6/0.4 on an open kitty, and back when the rule went).
  So a saved opacity shows on the app's open windows at once.
- **Sliders save 400 ms after the last move** (and on release), so dragging
  shows the result within half a second without a reload per pixel.
- Not `window.set_prop` for a preview: its value survives reloads and can't
  be unset (checked in the VM: `unset`, `default` and `""` are refused,
  `-1` sticks), so a previewed window would ignore every later rule change.
- Placement applies to windows opened after the change.

## What moves out of `rules.lua`

Into `windows.opacity` / `apps` defaults (same values):

| Today in `rules.lua` | Becomes |
|---|---|
| `default-opacity` tag → `0.97 0.9` | `windows.opacity` |
| browsers (chromium/firefox tags) → `1.0 0.97` | entries for each class the tags cover: `firefox`, `zen`, `librewolf`, `chromium`, `google-chrome`, `brave-browser`, `microsoft-edge`, `vivaldi-stable`, `helium` |
| `zen` → `1.0 override` ×3 | `zen` → 1 / 1 (overrides the browser value, as now) |
| `vesktop`, `limusic-app` → opaque, workspace 9 | entries with 1 / 1 and workspace 9 |
| `spotify` → workspace 9 | `spotify` → workspace 9 |
| `qemu`, `com.libretro.RetroArch`, `steam` → `1 1` | entries with 1 / 1 |
| media (`zoom`, `vlc`, `mpv`, `org.kde.kdenlive`, `com.obsproject.Studio`, `com.github.PintaProject.Pinta`, `imv`, `org.gnome.NautilusPreviewer`) → `1 1` | entries with 1 / 1 |
| terminals (`Alacritty`, `kitty`, `com.mitchellh.ghostty`, `foot`): opted out of the default, fixed at `0.97 0.9` | entries with 0.97 / 0.9 (they keep these when the default changes, as now) |

The `-default-opacity` opt-outs for these go, and so does the `terminal` tag
(it only set opacity); the browser tags stay, since Chromium's always-tile
rule uses them. What's left in `rules.lua` touching opacity:

- `pip` windows (matched by title) → `1 1`;
- `steam.*` (Steam's helper windows and every game) → `1 1`, and
  `steam_app_\d+` → `1.0 override`.

These are patterns, not classes, so they stay (the `steam` entry keeps the
page truthful for Steam's main window); a page entry for the same class
still wins (it loads after).

Case variants the tag regexes allowed (`Firefox`, `Chromium`, `Brave-browser`,
`Vivaldi-stable`, `Microsoft-edge`, `Google-chrome`) aren't separate entries:
the classes current builds report are lowercase. A browser reporting
otherwise shows up in the page as its own app with the default opacity.

## The page: Settings › Apps

```
 Apps
 ┌─────────────────────────────────────────────────────────────┐
 │ Default for every window                                     │
 │  Focused   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━○  97%  │
 │  Unfocused ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━○──── 90%   │
 └─────────────────────────────────────────────────────────────┘
  Open now
  [icon] Vesktop        vesktop · 1 window      100% / 100% · ws 9  ›
  [icon] kitty          kitty · 3 windows        default            ›
     ┌ Opacity   ( Default | Own )
     │  Focused   ━━━━━━━━━━━━━━━━━━━━━━○──────  90%
     │  Unfocused ━━━━━━━━━━━━━━━━○────────────  75%
     │ Opens on  ( Anywhere | Workspace | Monitor )
     │  Monitor  ( Acer X34 | BenQ left | BenQ right )
     │  Placement takes effect for windows opened from now on.
     └                                        [ Forget kitty ]
  Configured, not open
  [icon] Spotify        spotify                  ws 9               ›
  …
```

- **Open now**: one row per class among the open windows (their Wayland app
  id from `ToplevelManager.toplevels`, which XWayland windows fill with their
  class; live as windows come and go), with the window count. The name and icon come from
  the app's desktop entry (`DesktopEntries.heuristicLookup(class)`), else the
  class; the class is always shown, small, since that is what's matched.
  Quickshell's own windows (`org.quickshell`) are left out.
- **Configured, not open**: entries in `apps` with no open window, so an app
  can be set up before it runs (the defaults list lands here).
- **A row** shows a summary: its opacity (or "default") and placement. Click
  expands the editor; one open at a time.
- **Opacity**: Default / Own. Own shows the two sliders (10–100 %), starting
  from the default's values. Back to Default removes the app's `opacity`.
- **Opens on**: Anywhere / Workspace (a stepper, 1–10) / Monitor (one choice
  per connected monitor, labelled like Displays: the description without
  `desc:`). A configured monitor that isn't connected stays selected, shown
  as "(not connected)".
- **Forget**: removes the entry (`null` for a default one) — only when it
  has one.
- Below the list, an **Add by class** field, for an app that isn't open and
  isn't listed (`class` as Hyprland reports it).
- `Settings.lastError` shows a refused write, as on the other pages.
- **Restore the shipped setting** on a shipped entry the user changed
  (resets the user's override).
- `qs -c fledge ipc call settings app <class>` opens the page with that
  app's row open (listed even with no entry yet): for a bind on the focused
  window, and for the tests.

## Testing

All in the `cachyos-test` VM.

- `test-settings.sh`: `check` accepts the shipped defaults and the examples
  above; refuses opacity out of range or half given, workspace 0 or a
  string, a monitor with a comma, workspace and monitor together, unknown
  fields; an `apps` entry set to `null` disappears from the merge.
- `gen-apps.jq` (in `test-settings.sh`): the default rule, an opacity rule
  with `override`, a workspace and a monitor rule, a class with regex and Lua
  specials (`com.libretro.RetroArch`, `a"b\c`) escaped; no `apps` and no
  `windows` give just the header.
- `test-hypr-load.sh` / `test-lua-syntax.sh`: `apps.lua` from the defaults
  loads clean against the `hl` stub.
- `verify-shell.sh`: after `apply`, an open kitty reads the default opacity
  (`hyprctl getprop`); setting `.apps.kitty.opacity` and applying changes it
  on the open window; resetting it brings the default back; a `workspace`
  entry opens a new kitty on that workspace; `settings open apps` shows the
  page and lists kitty under Open now.
- By hand: the screenshot of the page with a few apps open.
