# fledge update: plan

Spec: `docs/superpowers/specs/2026-10-23-update-design.md`.
Branch: `update`. Everything runs in the `cachyos-test` VM.

## 0. Spikes (in the VM)

- [x] `snapper -c root create-config /` with the installer's `@/.snapshots`:
      what it refuses, and whether deleting the empty subvolume first is enough.
- [x] `limine-snapper-sync`: which unit to enable, and that a new snapshot
      lands in `/boot/limine.conf` with the installer's UKI setup.
- [x] `checkupdates`, `paru -Qua`, `fwupdmgr get-updates --json` outputs and
      exit codes for "nothing" and "offline".

## 1. The command

- [x] `lib/update.sh`: `update_main` (`check [--json]`, the run, `--yes`),
      dev-checkout rules, the steps, failure message naming the snapshot,
      reboot detection. Test hooks: `FLEDGE_REPO`, `FLEDGE_MODULES_DIR`.
- [x] `bin/fledge`: `update` with no action, `check` or a flag goes to
      `lib/update.sh`; `update firmware|time` still resolve to libexec;
      `fledge version`; help text for both.
- [x] `test/test-update.sh`: stubs on `PATH`, a scratch repo with a local
      origin and tags; check output, dev rules, order, failure, nothing
      pending, reboot detection.

## 2. Bootstrap

- [x] Packages: `snapper`, `limine-snapper-sync`, `pacman-contrib`, `fwupd`.
- [x] The `root` snapper config (btrfs `/` only) and its limits; the sync
      service enabled.

## 3. The shell

- [x] `services/Updates.qml`: the check 2 min after start and every 6 h, one
      at a time; `pending`, `summary`; `recheck()`.
- [x] `bar/modules/Updates.qml` + `Section.qml` choice; `updates` in
      `bar.right` defaults, `check.jq`'s module list and the Bar page.
- [x] Click runs `fledge update` in the floating terminal and re-checks
      when it exits. IPC `shell updates` (the summary) and `shell recheck`.
- [x] Menu: Update in Setup.

## 4. Docs and checks

- [x] README "Upgrade": `fledge update`; AGENTS.md: the repo is public.
- [x] `verify-update.sh`: snapper config and sync service; a scratch clone at
      an older tag with a local origin carrying a newer one; `fledge update
      --yes` takes pre/post, fast-forwards, runs that release's (stub)
      bootstrap; the snapshot is in `limine.conf`.
- [x] Unit tests, `verify-shell.sh`, shellcheck, `check-names.sh`,
      `check-stow-ignore.sh`.

## 5. Recovery (after review)

- [x] Spike in the VM: boot a snapshot through Limine, what `/proc/cmdline`
      says, what works read-only, `limine-snapper-restore`'s prompts (tty
      only), its stale lock, the package's lost notification.
- [x] `update.sh`: no `undochange`; the guide (try again / go back / leave
      it) on failure and Ctrl+C (exit 1); `update.json` runs; `recover`
      (booted: restore; otherwise the last failed run, or the snapshots).
- [x] Bootstrap records what it finished; `check` re-offers an unfinished
      one; the run marks it before running it.
- [x] Reboot prompt from the boot-time packages too.
- [x] Bootstrap: `EXCLUDE_SNAPSHOT_TYPES="post"`; hide the package's restore
      autostart (and unfold a folded `~/.config/autostart`).
- [x] Shell: `Recovery` service, `RecoveryDialog`, the bar module's
      snapshot state, IPC `recovery`.
- [x] `vm.sh reboot [snapshot]`, `verify-recovery.sh`; unit tests; full
      sweep (verify-shell 99/99, verify-update fresh, verify-commands).
